# Парсер автомобильных объявлений

Приложение для поиска и анализа объявлений по марке и модели. Реализованы
адаптеры Avito, Auto.ru и Drom, единая модель объявления, сохранение в SQLite,
аналитика рынка и гараж с историей обслуживания.

## Выбранный стек

- Python 3.11+;
- стандартный HTTP-клиент и `html.parser` — для лёгкого MVP без зависимостей;
- JSON-LD как более устойчивый источник данных, чем CSS-классы сайта;
- SQLite — для актуального состояния объявлений и истории цен;
- `unittest` — для проверки адаптеров на сохранённых HTML-фикстурах.

Если проект вырастет, разумный следующий стек: `httpx` для HTTP и повторных
запросов, `selectolax` для HTML, `pydantic-settings` для конфигурации,
`SQLAlchemy` + PostgreSQL для хранения, `APScheduler` или Celery для запуска
по расписанию. Playwright стоит добавлять только для разрешённых страниц,
данные которых действительно недоступны без JavaScript.

## Запуск

Создайте новое окружение: лежащая в репозитории `.venv` может быть привязана к
пути прежней установки Python.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
```

Запуск из корня проекта:

```powershell
python main.py "Toyota Camry"
python main.py "BMW E39" --region tver --radius 200
python main.py "BMW E39" --region tver --radius 200 --debug
python main.py "BMW E39" --region tver --radius 200 --details-limit 10
python main.py "Volvo XC90" --region tver --radius 200
python main.py "BMW X5" --region tver --radius 200 --limit 10
python main.py "Lada Vesta" --json
python main.py "Ford Focus" --source auto_ru --region tver
python main.py "BMW E39" --source drom --region tver --radius 200
```

По умолчанию парсер проходит страницы до конца выдачи и сохраняет до 200
уникальных объявлений. Число страниц можно ограничить явно, а лимит объявлений
изменить:

```powershell
python main.py "Volvo XC90" --region tver --radius 200 `
  --search-limit 300 --search-pages 8
```

Значение `--search-pages 0` означает проход без ограничения по числу страниц.

`--limit` управляет только количеством карточек, напечатанных в консоли, и не
ограничивает сохранение в SQLite.

Можно передать скопированный из браузера URL с любыми фильтрами:

```powershell
python main.py --url "https://www.avito.ru/tver/avtomobili/..."
python main.py --url "https://auto.ru/tver/cars/ford/focus/23054075/all/"
python main.py --url "https://auto.drom.ru/tver/bmw/all/?order=price#tabs"
```

Drom разбирается по устойчивым `data-ftid`-маркерам и JSON-LD. Поддерживаются
марочные пути `/bmw/all/`, модельные пути `/bmw/5-series/`, пагинация
`/page2/`, цена, пробег, статус снятого объявления, описание,
характеристики, просмотры и галерея. Для точного набора фильтров удобнее
передавать скопированную ссылку Drom; для распространённых запросов вроде
`BMW E39`, `Toyota Camry`, `Volkswagen Passat` и `Volvo XC90` доступны готовые
категорийные пути.

Для `BMW E39`, `Toyota Camry` и `Volkswagen Passat` используются точные
категорийные пути из Avito. Для остальных запросов применяется универсальный
текстовый поиск `?q=...`. Если точный путь вернул пустой результат, приложение
само повторяет запрос через текстовый поиск. Параметр `context` из браузерной
ссылки копировать
необязательно: он содержит служебное состояние интерфейса, а не основной набор
фильтров.

По умолчанию в консоль выводятся URL, результат проверки `robots.txt`, HTTP-код,
размер ответа и количество распознанных карточек. `--debug` добавляет заголовки
ответа и сведения о задержках. CAPTCHA или страница ограничения доступа
показывается как явная ошибка, а не как «найдено 0».

После получения выдачи приложение последовательно открывает первые 5 карточек,
чтобы дополнить полное описание и пробег. Число меняется через
`--details-limit`; значение `0` отключает переходы. Используется одна
cookie-сессия, `Referer`, проверка `robots.txt` и пауза между запросами. При
HTTP 429/439 цикл сразу останавливается и не пытается обходить ограничение.

Изображения первых 5 объявлений кэшируются в `.cache/auto_parser/images`.
По умолчанию сохраняется до 5 фото на объявление:

```powershell
python main.py "Volvo XC90" --region tver --radius 200 `
  --images-limit 10 --images-per-listing 3
```

Кэш можно отключить через `--images-limit 0` или перенести с помощью
`--cache-dir`. Повторно существующие файлы не загружаются. URL и локальные пути
сохраняются в таблице SQLite `listing_images`.

Чтобы сохранить все фотографии из найденной галереи:

```powershell
python main.py "Volvo XC90" --region tver --radius 200 `
  --images-limit 1 --images-per-listing 0
```

Пример карточки:

```text
[1] Toyota Camry, 2020
Цена:     2 750 000 руб.
Описание: Один владелец. Кузов без ДТП.
Место:    Москва
Ссылка:   https://www.avito.ru/...
```

Результаты сохраняются в `listings.db`. Другой путь задаётся флагом
`--database`. При повторном запуске карточка обновляется, а новая цена
добавляется в `price_history`.

## Веб-панель

Запустите локальную панель поверх текущей `listings.db`:

```powershell
python main.py --viewer
```

Затем откройте `http://127.0.0.1:8080`. Другие база, кэш или порт:

```powershell
python main.py --viewer --database listings.db `
  --cache-dir ".cache/auto_parser/images" --viewer-port 8090
```

Панель по умолчанию доступна только локально. Для привязки к нелокальному
адресу требуется одновременно указать `--viewer-host` и явный флаг
`--allow-remote-viewer`; открывать такой порт в недоверенной сети не следует.

Панель показывает карточки с локальными фото, поиск, фильтры минимальной и
максимальной цены/пробега, фильтр города, сортировку и пагинацию. Аналитика
пересчитывается с учётом активных фильтров: медианная и средняя цена, медианный
пробег, корреляция цены с пробегом, полнота описаний и фото, ценовые/пробеговые
диапазоны, география и последние снижения цены.

Раздел «Расширенные фильтры» формируется по характеристикам из базы. Доступны
год выпуска, тип и объём двигателя, коробка, привод, кузов, цвет, владельцы,
ПТС и состояние. В каждой группе можно отметить несколько вариантов: значения
одной группы объединяются через «или», разные группы — через «и». Эти условия
одинаково применяются к каталогу, статистике и аналитике рынка.

Карточку можно скрыть из каталога кнопкой «Скрыть». Состояние записывается в
SQLite и сохраняется после перезагрузки страницы и повторного сбора объявления.
Фильтр «Видимость» позволяет открыть скрытые карточки и вернуть их обратно.
Скрытие влияет только на каталог: статистика и анализ рынка продолжают учитывать
такие объявления.

Кнопка «+ В гараж» на карточке создаёт автомобиль из данных объявления. После
добавления кнопка меняет состояние на «В гараже», а автомобиль появляется во
вкладке гаража вместе с характеристиками, пробегом и исходной ссылкой.

Вкладка «Автозапчасти» импортирует списки `baza.drom.ru` для конкретной модели,
поколения и модификации. В SQLite сохраняются фото, название, описание, цена,
продавец и исходная ссылка. Предложения автоматически сопоставляются с маркой,
моделью, годом, типом топлива и объёмом двигателя объявления. Если в анализе
слабого места указано поле `replacement_parts`, подходящие товары показываются
прямо в карточке автомобиля; там же рассчитываются запчасти, работы, ожидаемые
вложения и итоговая стоимость входа с учётом цены автомобиля.

Категории Drom сохраняются иерархически: например, ссылка с тегом
`оптика+задний+фонарь` записывается как «Оптика → задний фонарь». Для деталей из
`replacement_parts` панель формирует точные вложенные ссылки и запрашивает их
последовательно с паузой. Если Drom показывает проверку «Вы не робот?», импорт
немедленно прекращает дополнительные запросы и предлагает открыть страницу для
ручной проверки; CAPTCHA и другие защитные механизмы автоматически не обходятся.

Для импорта уже подтверждённой страницы во вкладке «Автозапчасти» есть кнопка
«AutoScope: импорт Drom». Её нужно один раз перетащить в панель закладок
браузера. После ручного прохождения CAPTCHA нажмите закладку на странице списка:
она откроет локальное окно AutoScope и передаст туда текущий HTML. Количество
страниц выбирается в форме импорта (до 10): следующие страницы открываются
последовательно в той же вкладке и с той же подтверждённой сессией браузера.
Cookie в AutoScope не передаются, CAPTCHA автоматически не решается; при новой
проверке сбор следующих страниц прекращается, а уже полученные сохраняются.

Каталог запчастей поддерживает поиск, вкладки категорий, фильтры по автомобилю,
поколению, цене и наличию цены, варианты сортировки и постраничный просмотр.
Карточка автомобиля показывает не только точные совпадения со слабыми местами,
но и отдельную подборку совместимых импортированных запчастей модели/поколения.
Связь неисправности с товаром хранится в `repair_parts`: для каждого компонента
записываются стабильный тип, точные поисковые синонимы и исключающие термины.
Общие слова из описания неисправности не используются для выбора товара.

После сохранения ответа «Слабые места» приложение автоматически запускает
подбор запчастей и расходников для выявленных уязвимостей. Кнопка «Собрать
автозапчасти» остаётся доступна для ручного повторного запуска. Приложение
строит ссылку по марке и модели, переносит фильтры топлива и объёма,
определяет поколение по году и формирует отдельные выдачи для всех тегов Drom:
интерьера, оптики, кузовных деталей, двигателя, трансмиссии, ходовой части и
других доступных категорий. Сформированные ссылки показываются рядом с
результатом сбора и могут быть открыты вручную.

Если Drom возвращает проверку «не робот», автоматический сбор прекращается,
панель показывает уведомление и добавляет в карточку ссылку для ручной проверки.
После её прохождения сбор можно повторить кнопкой.

### Фоновый режим и Docker

В панели «Автопоиск» можно добавить несколько моделей, регион, радиус и
интервал от 15 минут. Фоновый процесс открывает все найденные карточки,
обновляет цену, описание, дату, просмотры и характеристики, затем кэширует
одну обложку каждого объявления. Остальные фотографии докачиваются при первом
открытии карточки в веб-панели. Раз в час повторно проверяются уже сохранённые
активные объявления; HTTP 404/410 переводит запись в статус `inactive`.

Запуск панели вместе с планировщиком без Docker:

```powershell
python main.py --viewer --validation-interval 60
```

Фоновый планировщик включается вместе с веб-панелью автоматически. Для запуска
только интерфейса без автопоиска используйте `--no-scheduler`.

Новые объявления записываются в базу до загрузки подробностей. Открытая панель
проверяет изменения каждые две секунды, поэтому описание и обложка появляются
сразу после их сохранения. Каждые 15 минут планировщик выбирает неполные
карточки, а также карточки, которые не обновлялись больше суток. Для них заново
получаются цена, описание, просмотры, характеристики и список фотографий.

Поисковый профиль принимает как запрос `Volvo XC90`, так и полную HTTPS-ссылку
на выдачу Avito, Auto.ru или Drom. Источник выбирается отдельно, а вставленная ссылка
определяет источник автоматически. В окне автопоиска есть готовый профиль «Все
авто Твери» для выборки автомобилей с пробегом в радиусе 200 км.
Для профиля можно задать минимальную и максимальную цену; для Drom эти значения
передаются параметрами `minprice` и `maxprice`.

Важно: сервис всегда соблюдает `robots.txt`. На момент проверки Auto.ru запрещает
автоматическое получение страниц выдачи выбранным идентификатором приложения,
поэтому такой профиль завершится с понятным сообщением об ограничении, а не с
ложным результатом «0 объявлений». Адаптер разбора и хранение данных готовы для
разрешённого доступа или официального API.

### Автоматический импорт Auto.ru через почту

Auto.ru умеет присылать новые объявления из сохранённого поиска на электронную
почту. GetEasyAuto может раз в минуту читать такие письма по IMAP без отметки
«прочитано», извлекать объявления и автоматически сохранять их в общую базу.

1. Сохраните нужный поиск в личном кабинете Auto.ru и включите уведомления на
   электронную почту.
2. Скопируйте `.env.example` в `.env` и укажите IMAP-сервер, логин и пароль
   приложения почтового ящика.
3. Перезапустите сервис командой `docker compose up -d --build`.

Статус импорта отображается в окне «Уведомления». Пароль нигде не записывается в
SQLite и используется только из переменных окружения процесса.

В этом же окне создаются критерии подходящего автомобиля: запрос, марки и модели,
диапазон цены, максимальный пробег, годы выпуска, минимальная мощность, цвета и
типы двигателя. Проверка выполняется сразу при каждом добавлении или обновлении
объявления. Совпадения сохраняются в центре уведомлений и при разрешении браузера
показываются как системные уведомления.

Если Avito временно ограничивает запросы, следующий запуск начинает с ещё не
обработанных карточек. Cooldown поиска и фоновой догрузки разделены: ограничение
при открытии карточки не останавливает поиск новых объявлений. При повторных
ограничениях пауза растёт: 15, 30, 60, 120 и максимум 240 минут.

Все обращения к Avito проходят через единую приоритетную очередь и не
выполняются параллельно. Поиск и фоновые данные имеют отдельные часовые бюджеты
по 120 запросов. Cooldown, история бюджета и уровень backoff сохраняются в
SQLite, поэтому перезапуск приложения не сбрасывает защиту.

Кнопка «Выгрузить для ChatGPT» на странице аналитики скачивает JSON с текущими
фильтрами, описаниями, характеристиками, метриками полноты текста, сигналами
содержания и готовым промптом для анализа корреляций цены и пробега.

Запуск в контейнере:

```powershell
docker compose up -d --build
docker compose logs -f
```

Панель будет доступна на `http://127.0.0.1:8080`. Контейнер автоматически
перезапускается, использует текущую `listings.db` и сохраняет изображения в
`.cache/auto_parser/images`. Остановка:

```powershell
docker compose down
```

## На что обратить внимание

1. Сначала изучайте API, пользовательское соглашение и `robots.txt` каждой
   площадки. Этот проект не обходит CAPTCHA, авторизацию и ограничения доступа.
2. Каждый сайт оформляйте отдельным адаптером `Source`; общая модель и хранилище
   не должны зависеть от его HTML.
3. Ограничивайте частоту, добавляйте таймауты, backoff с jitter и кэш. Не
   запускайте параллельную загрузку без разрешённых лимитов.
4. Сохраняйте исходную HTML-фикстуру для каждого обнаруженного изменения
   разметки и только потом исправляйте парсер.
5. Не собирайте телефоны и другие персональные данные без законного основания.
   Для коммерческого продукта получите разрешение или официальный фид/API.
6. Полное описание часто отсутствует в поисковой выдаче. Текущий адаптер
   показывает его, только если оно присутствует в JSON-LD. Загрузка страниц
   каждой карточки должна быть отдельным, ограниченным и явно разрешённым
   режимом.

## Структура

```text
src/auto_parser/
├── cli.py             # аргументы и вывод
├── formatting.py      # форматирование карточек
├── models.py          # единая модель Listing
├── service.py         # robots.txt, rate limit и HTTP
├── storage.py         # SQLite и история цен
└── sources/
    ├── base.py        # контракт адаптера
    ├── avito.py       # URL и разбор страниц Avito
    ├── auto_ru.py     # URL, выдача и карточки Auto.ru
    └── drom.py        # URL, выдача и карточки Drom
```
